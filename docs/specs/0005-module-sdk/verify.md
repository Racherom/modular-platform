### Bindings and protection (milestone 2)
- [ ] `go test -race ./sdk/ -run TestHTTPBinding -v` → the generated `Uses.Echo` client reaches a running SDK provider with the binding token, the provider answers with `consumer`, and the token shows in neither `%+v` nor the logs → AC-6 (HTTP)
- [ ] `go test -race ./sdk/httpclient` → the token goes only to the binding's own scheme and host, below its base path; any answer below 500 counts as ready → AC-6, AC-9
- [ ] `go test -race ./sdk/ -run 'TestBindingAuth|TestClientsDirProblems|TestHiddenAndLinkedClients' -v` → no token, another binding's token, `Basic` and a truncated token each get 401 with one `unauthorized` problem; `/healthz` and `/readyz` stay open; a valid token makes `CallerModule` the file name; after a restart without `other`'s file only `other` is refused; a short token, a bad file name or a duplicate token is `invalid_binding`, an empty directory `missing`; hidden entries are skipped and a symlink counts → AC-7
- [ ] `go test -race ./sdk/ -run 'TestReadiness|TestUnboundOptional|TestBindingProblems' -v` → `/readyz` answers 503 while the required provider answers 5xx and logs `binding not ready` with the capability, then 200 once it answers (a 404 counts); an optional binding left unbound starts and its getter returns `sdk.ErrUnbound`; a bad `url` is `invalid`, an empty token file `missing`, an unreadable one `invalid`, each as `config: uses.echo.<key> (<ENV>): ...` → AC-9
- [ ] `go test -race ./libs/planner -run TestPlan/missing-token-mapping` → error `missing_token_mapping` at `modules.notoken.uses.greet`, while `caller` (which maps `token_file`) is fine → AC-12
- [ ] `go test -race ./libs/render -run SDK -v` → the golden files under `testdata/sdk-pair/golden/` match; `config/<i>.env` text is exact (required, optional and default lines, binding credential lines); both SDK services run as `${MP_UID}:${MP_GID}` with `MP_INSTANCE` and `MP_ENV_FILE`; the token is mounted on the consumer at `/run/secrets/uses/greet/token` and on the provider at `/run/secrets/clients/greet/consumer`; password and secret key files are listed in the README and never created by `setup.sh`; the whoami golden is unchanged → AC-12
- [ ] `task test:integration` (needs Docker) → `TestSDKPairEndToEnd` builds both pair images, renders the graph, fills `PAIR_GREETING`, runs `setup.sh` and `docker compose up --wait`; inside the consumer `/call` answers `200 hi consumer` and `http://provider:8080/hello` without a token answers `401`; no `sdk-pair` container is left afterwards → AC-12

## Value sourcing
- [ ] Start value: set `MP_PLANNER_RATE` in the process env and a different one in the env file → the process env wins and the source shows `env` → Value sourcing "Start load"
- [ ] Problem line: the value part is the catalog `config` key (`planner-rate`), the env part its `env` (`MP_PLANNER_RATE`), the env file line number counts from 1 → Value sourcing "Start problem line"
- [ ] Start log: unset `MP_ACME_URL` and `MP_CA_FILE` → `tls: plain`; set only one → refused with `tls_config` → Value sourcing "Start log"
- [ ] Provider auth: the file name in `MP_PLANNER_CLIENTS_DIR` is what `sdk.CallerModule` reports for that token → Value sourcing "Provider auth"
- [ ] Render `MP_INSTANCE`: rename an instance in `libs/render/testdata/sdk-pair/graph.yaml` → its service's `MP_INSTANCE`, its `config/<i>.env` name and the clients file name on the provider all follow the graph key → Value sourcing "Render" `MP_INSTANCE`
- [ ] Render binding `url`: an SDK provider gives `http://<provider>:8080`; a plain provider gives `provides.<cap>.port` with `postgres://` for a postgresql client and `http://` otherwise (`TestRenderSDKCredentials`) → Value sourcing "Render" binding `url`
- [ ] Render `token_file`, `clients_dir`, `sslmode`: the fixed paths `/run/secrets/uses/<C>/token` and `/run/secrets/clients/<C>`, and `sslmode` always `disable` → Value sourcing "Render"
- [ ] Setup `MP_UID`, `MP_GID`: run `sh setup.sh` in a rendered pair folder twice → `.env` gains `MP_UID=$(id -u)` and `MP_GID=$(id -g)` once; the second run prints `kept` and changes nothing → Value sourcing "Render / setup"
- [ ] Binding token value: `secrets/<consumer>/uses_<C>` is 64 hex characters and survives a second `setup.sh` → Value sourcing "Setup / apply"
- [ ] HTTP client `Authorization`: the bearer the provider sees is the content of the file `PAIR_GREET_TOKEN_FILE` names, trailing newline trimmed → Value sourcing "HTTP client"
- [ ] Readiness: point a required binding at a server answering 503 → `/readyz` 503 and one warning per poll; switch it to 404 → `/readyz` 200 → Value sourcing "Readiness" (HTTP only so far)
