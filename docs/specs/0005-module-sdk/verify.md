### Host name and TLS mode (milestone 3, build plan task 6)
- [ ] `go test -race ./sdk/ -run TestStartProblems -v` → `MP_DOMAIN=Graph.internal` and `MP_DOMAIN=graph..internal` each give `config: MP_DOMAIN (MP_DOMAIN): invalid: ...` in plain mode too → AC-8 (bootstrap names)
- [ ] `go test -race ./sdk/ -run 'TestTLSProblems|TestTLSHTTPSBindingToSDK' -v` → one line each: only `MP_ACME_URL` or only `MP_CA_FILE` set → `tls_config` naming the other; an `http://` ACME URL → `invalid`; an unreadable CA file or one without a PEM certificate → `config: MP_CA_FILE (MP_CA_FILE): tls_config: ...`; both set without `MP_DOMAIN` → `config: MP_DOMAIN (MP_DOMAIN): tls_config: ...`; `TM_ECHO_URL=http://echo.SDK-TEST.internal:8080` → `config: uses.echo.url (TM_ECHO_URL): downgrade_refused: echo.sdk-test.internal is a module on the sdk ...`; an `https://` URL to that host, or an `http://` URL outside `.sdk-test.internal`, starts → AC-8
- [ ] `go test -race ./sdk/ -run 'TestTLSMode|TestTLSUnreadyWithoutCertificate' -v` → with a fake certificate getter the module listens on its TLS port only; `/readyz` is 503 and `healthcheck` exits 1 until a certificate is held, then exits 0, and exits 1 again without `MP_CA_FILE` or without `MP_DOMAIN`; a call with the binding token answers 200 over TLS 1.3 for `tm.sdk-test.internal`; plain HTTP on the TLS port answers 400 and a TLS 1.2 only handshake fails, neither reaching the handler; the start log has `"host":"tm.sdk-test.internal","tls":"tls"` and no plain HTTP warning → AC-8, AC-9
- [ ] `go test -race ./sdk/tlsacme -v` → manager (fake issuer, `synctest`): a 24 hour certificate renews at 16 hours, a certificate whose two thirds point has passed renews 30 seconds after its issue; failed attempts retry 1, 2, 4, 8, 16, 30, 30 seconds apart with one `certificate issue failed` warning each while the held certificate keeps serving, and the backoff starts at 1 second again after a success; an attempt the issuer never answers is cut at 5 minutes; another name, a foreign CA, a key mismatch, under a minute left, an expired leaf, a CA clock 2 minutes ahead and no leaf are each refused as a failed attempt (a CA clock 30 seconds ahead passes); only an `acme-tls/1` only hello reaches `Challenge`, every other hello gets the held certificate whatever its server name; ready only with at least 2 hours left. Engine (`httptest` ACME stub): one `Issue` registers, orders the one name, answers the validation for that name only (upper case and a trailing dot accepted), empties the answer slot after, sends a CSR with an empty subject, the name alone and an ECDSA P-256 key, and returns the chain with a matching key; an account that already exists counts as registered; after `accountDoesNotExist` the next `Issue` registers again and no other `Issue` does; an order naming another identifier, an `invalid` or `expired` authorization and no `tls-alpn-01` challenge fail, a `valid` authorization skips validation → AC-8, AC-9
- [ ] `go test -race ./sdk/ -run TestTLSBindingTrust -v` → in TLS mode an `http` binding without its own `ca_file` trusts `MP_CA_FILE` and reaches a provider whose certificate that CA signed → AC-8 ("Clients trust `MP_CA_FILE`")
- [ ] `go test -race -tags integration ./sdk/ -run TestTLSAgainstPebble -v` (needs Docker, about 70 seconds) → against pebble v2.10.1 with `tlsPort` 8443, the module container (alias `tm.sdk-test.internal`) enrols through the SDK's ACME client over tls-alpn-01; with a 24 hour profile a client offering TLS 1.2 and 1.3 and a TLS 1.3 only client get the same ECDSA P-256 certificate and pebble logs one `POST /order-plz`, `GET /hello` answers `hi`, plain HTTP on 8443 fails, `healthcheck` exits 0 in the container and 1 with `MP_CA_FILE=`; with a 90 second profile the module presents a renewed certificate 25 to 35 seconds before the first expires, after a second order → AC-8, AC-9
- [ ] `go test -race ./sdk/caller -v` → a minted token verifies and carries `EdDSA`, the kid, `iss`, `sub`, `groups`, one `aud`, `iat`, `exp` 5 minutes later and a 16 byte `jti` (a fresh one per token); the kid matches RFC 8037 A.3 (`kPrK_qmxVWaYVA9wwBF6Iuo3vVzz7TxHCTwXBygrS4k`); an ECDSA key cannot mint; `Verify` refuses (`invalid_token`) another `aud`, the bare instance as `aud`, two `aud`s, `exp` passed by more than 30 seconds, `iat` more than 30 seconds ahead (29 seconds either way passes), no `exp` or `iat`, a lifetime over 5 minutes, an empty or missing `sub`, an unknown kid, a known kid signed by another key, `ES256`, `alg: none`, a tampered payload and anything not a compact JWS; the key files take PKIX and PKCS 8 Ed25519 PEM and refuse the rest without showing a key; the signer mints as its own instance and hides its key from `fmt` and `slog`; the middleware puts the caller into ctx, lets a request without the header through with no caller, and answers 401 `invalid_token` to the header twice, a call without binding token auth, a token passed on by another module (`iss` is not `CallerModule`) and another `aud`, logging the reason but never the token; with no key file the header is ignored and logged once → AC-11
- [ ] `go test -race ./sdk/ -run 'TestCaller' -v` → a consumer on the sdk holding `MP_CALLER_SIGNING_KEY_FILE` (as `api` does) sends the caller its code put into ctx with `sdk.WithCaller` to a provider on the sdk holding `MP_CALLER_KEY_FILE`, which sees `sdk.CallerFrom` = `{Issuer: caller, User: ada, Groups: [admins]}` and `sdk.CallerModule` = `caller`; without a caller in ctx no header is sent; a binding URL naming the provider by IP mints for that IP and gets 401; an unreadable or wrong key file stops the start with one `invalid` line naming the file → AC-11

## Value sourcing
- [ ] Start value: set `MP_PLANNER_RATE` in the process env and a different one in the env file → the process env wins and the source shows `env` → Value sourcing "Start load"
- [ ] Problem line: the value part is the catalog `config` key (`planner-rate`), the env part its `env` (`MP_PLANNER_RATE`), the env file line number counts from 1 → Value sourcing "Start problem line"
- [ ] Start log: unset `MP_ACME_URL` and `MP_CA_FILE` → `tls: plain`; set only one → refused with `tls_config` → Value sourcing "Start log"
- [ ] Provider auth: the file name in `MP_PLANNER_CLIENTS_DIR` is what `sdk.CallerModule` reports for that token → Value sourcing "Provider auth"
- [ ] Render `MP_INSTANCE`: rename an instance in `libs/render/testdata/sdk-pair/graph.yaml` → its service's `MP_INSTANCE`, its `config/<i>.env` name and the clients file name on the provider all follow the graph key → Value sourcing "Render" `MP_INSTANCE`
- [ ] Render `MP_DOMAIN` and alias: rename the graph in `libs/render/testdata/sdk-pair/graph.yaml` → every SDK service's `MP_DOMAIN`, its network alias and the consumer's binding URL host follow `<graph>.internal` → Value sourcing "Render" `MP_DOMAIN`, network alias
- [ ] Start host name: start the planner with `MP_DOMAIN=x.internal` → the `config loaded` line shows `host` `planner.x.internal`; without `MP_DOMAIN` it shows `planner` → Value sourcing "Start" host name
- [ ] Render binding `url`: an SDK provider gives `http://<provider>.<graph>.internal:8080`; a plain provider gives `provides.<cap>.port` with `postgres://` for a postgresql client and `http://` otherwise (`TestRenderSDKCredentials`) → Value sourcing "Render" binding `url`
- [ ] Render `token_file`, `clients_dir`, `sslmode`: the fixed paths `/run/secrets/uses/<C>/token` and `/run/secrets/clients/<C>`, and `sslmode` always `disable` → Value sourcing "Render"
- [ ] Setup `MP_UID`, `MP_GID`: run `sh setup.sh` in a rendered pair folder twice → `.env` gains `MP_UID=$(id -u)` and `MP_GID=$(id -g)` once; the second run prints `kept` and changes nothing → Value sourcing "Render / setup"
- [ ] Binding token value: `secrets/<consumer>/uses_<C>` is 64 hex characters and survives a second `setup.sh` → Value sourcing "Setup / apply"
- [ ] HTTP client `Authorization`: the bearer the provider sees is the content of the file `PAIR_GREET_TOKEN_FILE` names, trailing newline trimmed → Value sourcing "HTTP client"
- [ ] Readiness: point a required binding at a server answering 503 → `/readyz` 503 and one warning per poll; switch it to 404 → `/readyz` 200 → Value sourcing "Readiness" (HTTP only so far)
- [ ] Database, user, bucket, region, access key id: change `TM_DB_USER` or `TM_STORE_REGION` in the env (or an env file) → the pool's user and the client's signing region follow; leave `TM_STORE_REGION` unset → `us-east-1` → Value sourcing "Database, user, bucket, region, access key id"
- [ ] Password, secret key: the pool's password and the S3 secret key are the content of the files `TM_DB_PASSWORD_FILE` and `TM_STORE_SECRET_KEY_FILE` name, trailing newline trimmed; an empty file is `missing` → Value sourcing "Password, secret key"
- [ ] Readiness (data): PostgreSQL counts as answered after one `Ping`, S3 after `BucketExists` reports true; a sign in failure or a missing bucket keeps polling → Value sourcing "Readiness"
- [ ] TLS settings: unset either `MP_ACME_URL` or `MP_CA_FILE` → `tls_config` naming the other; both set → the start log says `tls` → Value sourcing "TLS"
- [ ] Certificate name: change `MP_INSTANCE` or `MP_DOMAIN` → the certificate the module asks for and serves names the new `<MP_INSTANCE>.<MP_DOMAIN>`; the healthcheck checks that same name → Value sourcing "Checking / TLS"
- [ ] Readiness (certificate): `/readyz` follows the held certificate's `NotAfter`: 200 with 2 hours or more left, 503 below → Value sourcing "Readiness" (certificate time left)
- [ ] Receiving a call: the provider's `sdk.CallerFrom` gives `User` from `sub`, `Groups` from `groups`, `Issuer` from `iss`, and only with a key file holding the minter's public key (`TestCallerEndToEnd`, `TestMiddleware`) → Value sourcing "Receiving a call"
- [ ] Minting `aud`: point the consumer's binding URL at `localhost:<port>` → accepted by the provider named `localhost`; at `127.0.0.1:<port>` → `aud` is `127.0.0.1` and the call gets 401 → Value sourcing "Minting" `aud`
- [ ] Minting `iss`: change the consumer's `MP_INSTANCE` → the provider's `Caller.Issuer` follows it, and a token whose `iss` is not the module the binding token proved gets 401 → Value sourcing "Minting" `iss`
- [ ] Minting `sub`, `groups`: the `Caller` passed to `sdk.WithCaller` is what the provider sees; an `Issuer` set by module code is replaced by the instance → Value sourcing "Minting" `sub`, `groups`
- [ ] `kid`: the header kid is the RFC 7638 thumbprint of the public key (`TestKID`), and a token whose kid is not in `MP_CALLER_KEY_FILE` gets 401 → Value sourcing "Minting / checking" `kid`

- [ ] Start load (start source): set the same value through the source, `TM_GREETING`, `TM_GREETING_FILE`, an env file and the default, then remove them one by one from the top → the getter and the `config loaded` label follow the highest one left (`source`, `env`, `file:<path>`, `env-file:<path>:<line>`, `default`) → Value sourcing "Start load"
- [ ] Start log (push and unset): push a snapshot that leaves out `count` and `note` → `count` shows `default`, `note` shows `unset`, a pushed value shows `push` → Value sourcing "Start log"
- [ ] Per caller value: ask `greeting` as `alice` (answered), as `bob` (not answered) and with no caller → `hi`, the snapshot value, the snapshot value; change the caller's groups → asked again, since the cache key holds the issuer, user and groups → Value sourcing "Per caller value"
