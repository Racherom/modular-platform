### Host name and TLS mode (milestone 3, build plan task 6)
- [ ] `go test -race ./sdk/ -run TestStartProblems -v` → `MP_DOMAIN=Graph.internal` and `MP_DOMAIN=graph..internal` each give `config: MP_DOMAIN (MP_DOMAIN): invalid: ...` in plain mode too → AC-8 (bootstrap names)
- [ ] `go test -race ./sdk/ -run 'TestTLSProblems|TestTLSHTTPSBindingToSDK' -v` → one line each: only `MP_ACME_URL` or only `MP_CA_FILE` set → `tls_config` naming the other; an `http://` ACME URL → `invalid`; an unreadable CA file or one without a PEM certificate → `config: MP_CA_FILE (MP_CA_FILE): tls_config: ...`; both set without `MP_DOMAIN` → `config: MP_DOMAIN (MP_DOMAIN): tls_config: ...`; `TM_ECHO_URL=http://echo.SDK-TEST.internal:8080` → `config: uses.echo.url (TM_ECHO_URL): downgrade_refused: echo.sdk-test.internal is a module on the sdk ...`; an `https://` URL to that host, or an `http://` URL outside `.sdk-test.internal`, starts → AC-8
- [ ] `go test -race ./sdk/ -run 'TestTLSMode|TestTLSUnreadyWithoutCertificate' -v` → with a fake certificate getter the module listens on its TLS port only; `/readyz` is 503 and `healthcheck` exits 1 until a certificate is held, then exits 0, and exits 1 again without `MP_CA_FILE` or without `MP_DOMAIN`; a call with the binding token answers 200 over TLS 1.3 for `tm.sdk-test.internal`; plain HTTP on the TLS port answers 400 and a TLS 1.2 only handshake fails, neither reaching the handler; the start log has `"host":"tm.sdk-test.internal","tls":"tls"` and no plain HTTP warning → AC-8, AC-9
- [ ] `go test -race ./sdk/tlsacme -v` → the getter always sees an ECDSA P-256 only hello (one suite, one scheme, one curve) with `ServerName` and `SupportedProtos` unchanged, also for an `acme-tls/1` validation hello, and the incoming hello stays untouched; enrolment asks with a hello holding only the host name and retries at 0, 1 and 3 seconds; `Ready` never asks autocert before enrolment; on a fake clock a 24 hour certificate is ready until 2 hours are left, then 503 while it keeps serving, with one `certificate expires soon` warning; a renewed certificate logs `certificate renewed`; `ACME` sets the directory, a host only policy, no cache and `RenewBefore` 0 → AC-8, AC-9
- [ ] `go test -race ./sdk/ -run TestTLSBindingTrust -v` → in TLS mode an `http` binding without its own `ca_file` trusts `MP_CA_FILE` and reaches a provider whose certificate that CA signed → AC-8 ("Clients trust `MP_CA_FILE`")
- [ ] `go test -race -tags integration ./sdk/ -run TestTLSAgainstPebble -v` (needs Docker, about 70 seconds) → against pebble v2.10.1 with `tlsPort` 8443, the module container (alias `tm.sdk-test.internal`) enrols over tls-alpn-01; with a 24 hour profile a client offering TLS 1.2 and 1.3 and a TLS 1.3 only client get the same ECDSA P-256 certificate and pebble logs one `POST /order-plz`, `GET /hello` answers `hi`, plain HTTP on 8443 fails, `healthcheck` exits 0 in the container and 1 with `MP_CA_FILE=`; with a 90 second profile the module presents a renewed certificate 20 to 30 seconds before the first expires, after a second order → AC-8, AC-9

## Value sourcing
- [ ] Start value: set `MP_PLANNER_RATE` in the process env and a different one in the env file → the process env wins and the source shows `env` → Value sourcing "Start load"
- [ ] Problem line: the value part is the catalog `config` key (`planner-rate`), the env part its `env` (`MP_PLANNER_RATE`), the env file line number counts from 1 → Value sourcing "Start problem line"
- [ ] Start log: unset `MP_ACME_URL` and `MP_CA_FILE` → `tls: plain`; set only one → refused with `tls_config` → Value sourcing "Start log"
- [ ] Provider auth: the file name in `MP_PLANNER_CLIENTS_DIR` is what `sdk.CallerModule` reports for that token → Value sourcing "Provider auth"
- [ ] Render `MP_INSTANCE`: rename an instance in `libs/render/testdata/sdk-pair/graph.yaml` → its service's `MP_INSTANCE`, its `config/<i>.env` name and the clients file name on the provider all follow the graph key → Value sourcing "Render" `MP_INSTANCE`
- [ ] Render `MP_DOMAIN` and alias: rename the graph in `libs/render/testdata/sdk-pair/graph.yaml` → every SDK service's `MP_DOMAIN`, its network alias and the consumer's binding URL host follow `<graph>.internal` → Value sourcing "Render" `MP_DOMAIN`, network alias
- [ ] Start host name: start the planner with `MP_DOMAIN=x.internal` → the `config loaded` line shows `host` `planner.x.internal`; without `MP_DOMAIN` it shows `planner` → Value sourcing "Start" host name
- [ ] Render binding `url`: an SDK provider gives `http://<provider>.<graph>.internal:8080`; a plain provider gives `provides.<cap>.port` with `postgres://` for a postgresql client and `http://` otherwise (`TestRenderSDKCredentials`) → Value sourcing "Render" binding `url`
- [ ] Render `token_file`, `clients_dir`, `sslmode`: the fixed paths `/run/secrets/uses/<C>/token` and `/run/secrets/clients/<C>`, and `sslmode` always `disable` → Value sourcing "Render"
- [ ] Setup `MP_UID`, `MP_GID`: run `sh setup.sh` in a rendered pair folder twice → `.env` gains `MP_UID=$(id -u)` and `MP_GID=$(id -g)` once; the second run prints `kept` and changes nothing → Value sourcing "Render / setup"
- [ ] Binding token value: `secrets/<consumer>/uses_<C>` is 64 hex characters and survives a second `setup.sh` → Value sourcing "Setup / apply"
- [ ] HTTP client `Authorization`: the bearer the provider sees is the content of the file `PAIR_GREET_TOKEN_FILE` names, trailing newline trimmed → Value sourcing "HTTP client"
- [ ] Readiness: point a required binding at a server answering 503 → `/readyz` 503 and one warning per poll; switch it to 404 → `/readyz` 200 → Value sourcing "Readiness" (HTTP only so far)
- [ ] Database, user, bucket, region, access key id: change `TM_DB_USER` or `TM_STORE_REGION` in the env (or an env file) → the pool's user and the client's signing region follow; leave `TM_STORE_REGION` unset → `us-east-1` → Value sourcing "Database, user, bucket, region, access key id"
- [ ] Password, secret key: the pool's password and the S3 secret key are the content of the files `TM_DB_PASSWORD_FILE` and `TM_STORE_SECRET_KEY_FILE` name, trailing newline trimmed; an empty file is `missing` → Value sourcing "Password, secret key"
- [ ] Readiness (data): PostgreSQL counts as answered after one `Ping`, S3 after `BucketExists` reports true; a sign in failure or a missing bucket keeps polling → Value sourcing "Readiness"
- [ ] TLS settings: unset either `MP_ACME_URL` or `MP_CA_FILE` → `tls_config` naming the other; both set → the start log says `tls` → Value sourcing "TLS"
- [ ] Certificate name: change `MP_INSTANCE` or `MP_DOMAIN` → the certificate the module asks for and serves names the new `<MP_INSTANCE>.<MP_DOMAIN>`; the healthcheck checks that same name → Value sourcing "Checking / TLS"
- [ ] Readiness (certificate): `/readyz` follows the held certificate's `NotAfter`: 200 with 2 hours or more left, 503 below → Value sourcing "Readiness" (certificate time left)
