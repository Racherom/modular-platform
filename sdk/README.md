# Module SDK

A Go kit for building a module container. You describe your module once, in its catalog entry: the config values it needs, the capabilities it uses, the one it provides. The SDK does the rest. It loads and checks every value at start, opens ready clients for your bindings, checks a token on every incoming call, serves TLS when an issuer is bound, and answers `/healthz` and `/readyz`.

- The design and its reasons: [spec 0005](../docs/specs/0005-module-sdk/index.md)
- The rules a second language SDK, a config server or a policy server must follow: [CONTRACT.md](CONTRACT.md)
- Conventions for working on the SDK itself: [AGENTS.md](AGENTS.md)

## Build a module on the SDK

The renderer runs on the SDK; [catalog/modules/renderer/module.yaml](../catalog/modules/renderer/module.yaml) and [services/renderer](../services/renderer/) are a full example.

### 1. Declare the module in its catalog entry

Add `runtime: sdk`, your values under `config:`, a `client` on each binding you want a ready client for, and `auth: binding-token` on what you provide:

```yaml
apiVersion: modular-platform/v0alpha1
kind: Module
name: notes
description: Keeps notes for a user.
image: ghcr.io/example/notes:1.0.0
runtime: sdk
healthcheck:
  test: ["CMD", "/notes", "healthcheck"]
  start_period: 30s
provides:
  notes:
    auth: binding-token
    env:
      clients_dir: NOTES_CLIENTS_DIR
uses:
  postgresql:
    client: postgresql
    env:
      url: NOTES_DB_URL
      database: NOTES_DB_NAME
      user: NOTES_DB_USER
      password_file: NOTES_DB_PASSWORD_FILE
      sslmode: NOTES_DB_SSLMODE
config:
  page-size:
    env: NOTES_PAGE_SIZE
    type: int
    default: "50"
    min: 1
    max: 500
    description: The most notes one page lists.
```

The types are `string`, `int`, `bool`, `duration`, `url`, `enum` and `secret`; the rules per type are in [CONTRACT.md, section 1](CONTRACT.md#1-catalog-entry-fields). The catalog check and `sdkgen` both refuse an entry that breaks one, with the same lines.

### 2. Generate the getters

Put a `generate.go` in `internal/config/`:

```go
// Package config holds the module's declared values, generated by sdkgen from its catalog entry.
package config

//go:generate go tool sdkgen -entry ../../../../catalog/notes.yaml -package config -out config.gen.go
```

and add the tool to your module's `go.mod`:

```text
tool github.com/racherom/modular-platform/sdk/cmd/sdkgen
```

`task generate` runs it and writes `config.gen.go`: a `Config` type with one getter per value (`PageSize(ctx) (int, error)`), a `Uses` type with one getter per client binding (`Postgresql(ctx) (*pgxpool.Pool, error)`), and the `Module` declaration. Never edit that file by hand; change the entry and generate again.

### 3. Run it

```go
func main() { sdk.Run(config.Module, setup) }

func setup(ctx context.Context, m *sdk.Module[config.Config, config.Uses]) (http.Handler, error) {
	size, err := m.Config.PageSize(ctx)
	if err != nil {
		return nil, err
	}
	db, err := m.Uses.Postgresql(ctx)
	if err != nil {
		return nil, err
	}
	return newHandler(db, size, m.Log), nil
}
```

`sdk.Run` also handles the `healthcheck` subcommand, signals, the JSON logger and graceful shutdown. A few things you can do from `setup`:

- read the calling module with `sdk.CallerModule(r.Context())` and the calling user with `sdk.CallerFrom(r.Context())` in your handler;
- turn the binding token check off with `m.AllowAnonymous()` (the renderer does in public mode), or add a rate limit with `m.WithRateLimit`;
- give `Config` a `Validate(ctx) error` method for a check across values; its error refuses the start like any bad value;
- log your own reasons and return an error that wraps `sdk.ErrStart`, so the SDK does not log the failure a second time.

Read values only through the getters, never from `os.Getenv`. Getters take `ctx` and return an error because a later per caller source may answer them differently for each user.

## Configure a running module

You set a value in one of these places, highest first (the full rules are in [CONTRACT.md, section 3](CONTRACT.md#3-where-a-declared-value-comes-from)):

1. the env var, like `NOTES_PAGE_SIZE=100`, or a file it names, like `NOTES_PAGE_SIZE_FILE=/run/secrets/size`
2. a line in one of the env files listed in `MP_ENV_FILE` (separated by `:`, a later file above an earlier one)
3. the `default` from the catalog entry

A `secret` never comes from a plain env var; give it as a file. The render writes `config/<instance>.env` for each module with every value commented, so you can fill in what is required and restart.

A bad start names every problem at once, then stops with exit code 1 before it listens:

```text
config: page-size (NOTES_PAGE_SIZE): out_of_range: 0 is below the minimum 1
config: uses.postgresql.user (NOTES_DB_USER): missing: a value is required; set NOTES_DB_USER
```

A good start logs one `config loaded` line that shows where each value came from (never the value itself), the host name, the TLS mode and each binding's client kind.

The SDK also reads a few bootstrap names from the process env, which the render fills in for you: `MP_INSTANCE`, `MP_DOMAIN`, `MP_ENV_FILE`, `MP_ACME_URL`, `MP_CA_FILE` and `MP_CALLER_SIGNING_KEY_FILE` ([CONTRACT.md, section 2](CONTRACT.md#2-bootstrap-names)).

## Test a module

- `sdk.Build` gives you the module's full handler (middleware, `/healthz`, `/readyz`) without listening, so you can drive it with `httptest`. Pass `sdk.WithEnv` to set the whole env and `sdk.WithLogger` to catch the logs.
- [sdktest](sdktest/) writes env files and clients directories and holds fakes of the pluggable sources.

## Packages

| Package | What it holds |
|---|---|
| `sdk` | `Run`, `Build`, the declaration types, `Secret`, `Caller`, the source interfaces and options |
| [manifest](manifest/) | the catalog entry fields the SDK reads and their rules (also used by the catalog check) |
| [envfile](envfile/) | the strict env file parser |
| [httpkit](httpkit/) | logger, problem answers, health, access log, rate limit, client IP, base path, serving |
| [auth](auth/) | the per consumer binding token check |
| [caller](caller/) | minting and checking the `MP-Caller` token |
| [tlsacme](tlsacme/) | the ACME client and the certificate manager for TLS mode |
| [httpclient](httpclient/), [pg](pg/), [s3](s3/) | the three binding clients |
| [sdktest](sdktest/) | test helpers and fakes |
| [cmd/sdkgen](cmd/sdkgen/) | the generator |

## Tests

```bash
go test -race ./sdk/...                       # everything that needs no Docker (task test)
go test -race -tags integration ./sdk/...     # also PostgreSQL, MinIO and pebble, through Docker
```

`TestContract` checks that every statement in [CONTRACT.md](CONTRACT.md) names a test that exists, so when you change a rule, change its statement and its test together.
